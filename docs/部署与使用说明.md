# 部署与使用说明书

竞赛辅助服务智能体 v1.0
适用对象：系统管理员、竞赛秘书、指导教师

---

## 1. 环境要求

| 项 | 要求 |
| --- | --- |
| 操作系统 | Windows 10/11、macOS 12+、Ubuntu 20.04+ |
| Python | 3.10 及以上（开发与测试使用 3.13） |
| 内存 | 建议 2 GB 以上（纯文本索引，无需 GPU） |
| 磁盘 | 500 MB 起（含样例数据与知识库） |
| 网络 | 初始化与下载前端依赖时需要；运行时可离线（本地向量模式 + 本地 vendor） |
| 数据库 | 默认 SQLite，可直接切换 MySQL 8 / PostgreSQL 14 |

不需要 Elasticsearch、Milvus、Chroma 等外部服务，检索索引在进程内构建。

## 2. 安装

### 2.1 创建虚拟环境

Windows PowerShell：

```powershell
cd competition-agent
python -m venv .venv
.venv\Scripts\activate
```

macOS / Linux：

```bash
cd competition-agent
python3 -m venv .venv
source .venv/bin/activate
```

PyCharm 用户：打开项目 → Settings → Project → Python Interpreter → Add Interpreter → Existing → 选择 `.venv/Scripts/python.exe`。

### 2.2 安装依赖

```bash
pip install -r requirements.txt
```

依赖清单（共 8 个，均为纯 Python 或有预编译包）：

```
fastapi  uvicorn  SQLAlchemy  python-multipart
pypdf    python-docx  openpyxl  jieba
```

`jieba` 缺失不影响运行，系统会自动退化为字符级分词。

### 2.3 下载前端依赖

```bash
python scripts/fetch_vendor.py
```

该脚本从多个 CDN（unpkg / jsdelivr / npmmirror / staticfile）依次尝试，把 `vue.global.prod.js` 与 `echarts.min.js` 下载到 `frontend/vendor/`。下载成功后前端完全离线可用。

若网络不通，也可手动从上述任一 CDN 下载这两个文件放入 `frontend/vendor/`。

## 3. 初始化与启动

### 3.1 一键初始化

```bash
python scripts/init_all.py
```

依次完成：

1. 建表（`data/app.db`）
2. 生成样例台账：22 名教师、180 名学生、15 项赛事、约 300 个参赛项目及获奖记录
3. 生成 6 份知识库文档到 `data/knowledge/`（管理办法、经费细则、两份竞赛规程、申报书规范、学生指南）
4. 解析入库：切块 + 向量化 + 建索引

输出示例：

```
[1/4] 建表  …  sqlite:///C:/.../data/app.db
[2/4] 生成样例台账数据 …
      students       180
      competitions   15
      teams          297
      awards         118
[3/4] 生成知识库文档 …
[4/4] 导入知识库（切块 + 向量化）…
      成功 6 份，失败 0 份

  知识库：6 份文档 / 25 个片段
```

如需清空重建：`python scripts/init_all.py --force`

### 3.2 启动

```bash
python run.py                 # 默认 127.0.0.1:8000，自动打开浏览器
python run.py --port 9000     # 换端口
python run.py --no-browser    # 不自动开浏览器
python run.py --no-reload     # 关闭热重载（生产环境用）
```

启动后：

- 系统界面：`http://127.0.0.1:8000`
- 接口文档：`http://127.0.0.1:8000/api/docs`（可直接在线调试全部接口）

## 4. 配置说明

复制 `.env.example` 为 `.env`，按需修改。**未创建 `.env` 时全部使用默认值，系统可正常运行。**

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `DATABASE_URL` | `sqlite:///./data/app.db` | 数据库连接串，见第 7 节 |
| `LLM_PROVIDER` | `mock` | `deepseek` / `qwen` / `doubao` / `openai` / `ollama` / `mock` |
| `LLM_API_KEY` | 空 | 大模型密钥 |
| `LLM_MODEL` | 按厂商默认 | 模型名，豆包需填接入点 ID |
| `LLM_BASE_URL` | 按厂商默认 | 自定义兼容端点 |
| `EMBEDDING_MODE` | `local` | `local` 内置哈希向量（离线）；`api` 调用厂商 embedding 接口 |
| `RETRIEVE_TOP_K` | 6 | 每次检索返回片段数 |
| `RETRIEVE_MIN_SCORE` | 0.12 | 低于该分数视为未命中，触发"知识库未收录"回答 |
| `RETRIEVE_BM25_WEIGHT` | 0.5 | 关键词通道权重 |
| `RETRIEVE_VECTOR_WEIGHT` | 0.5 | 语义通道权重 |
| `PORT` | 8000 | 监听端口 |

### 关于 `mock` 模式

`LLM_PROVIDER=mock` 或未填 Key 时，系统的全部功能仍然可用，区别在于：

| 能力 | 有模型 | 无模型 |
| --- | --- | --- |
| 知识问答 | 模型基于片段组织表述 | 抽取原文句子重组，带引用 |
| 竞赛推荐 | 规则打分 + 模型重排序与理由 | 纯规则打分 + 分层 |
| 备赛计划 | 模型结合规程生成细化方案 | 按赛程天数规则倒排 |
| 材料评审 | 逐项分析给改写建议 | 结构/篇幅/空话/数据密度启发式检查 |
| 数据统计 | 自然语言转查询条件 | 正则抽取年份/级别/维度 |
| 预算/借款/报销 | 模型做制度比对 | 纯规则校验（结果一致，模型仅补文字说明） |

**降级路径下的所有数字、日期、金额、名单一律来自数据库与规则计算，不由模型生成。** 这也是本系统的核心设计约束。

### 推荐配置（性价比）

```ini
LLM_PROVIDER=deepseek
LLM_API_KEY=sk-xxxxxxxxxxxxxxxx
LLM_MODEL=deepseek-chat
EMBEDDING_MODE=local
```

DeepSeek 输入价格低，问答类任务够用；向量仍走本地，避免额外出网依赖。

## 5. 界面使用

### 5.1 知识问答

- 输入问题后按 `Ctrl+Enter` 或点发送。
- 回答下方列出引用来源（文档名、类别、页码），点「查看原文」可展开完整片段，用于核对与答辩举证。
- 回答上方标签显示本条走的是「大模型生成」还是「原文抽取」。
- 展开「Agent 执行过程」可看到每个节点的耗时，便于演示与排障。
- 左侧为历史会话列表，可新建、切换、删除。

建议演示问题：

| 问题 | 预期命中 |
| --- | --- |
| 国创赛校赛报名截止时间是什么时候？ | 规程第四条：2026 年 4 月 20 日 17:00 |
| 省外参赛住宿费标准是多少？ | 经费细则第六条：380 元/人天 |
| 报销要准备哪些材料？ | 细则第十七条材料清单 |
| ACM 区域赛允许带纸质资料吗？ | ACM 规程第六条 |
| 申报书缺少实验数据会怎样？ | 撰写规范"常见问题"第二条 |

### 5.2 知识库

- 支持 `.pdf .docx .xlsx .csv .md .txt`，可多选或拖拽。
- 「文档类别」「年份」可留空自动识别。
- 右上「检索测试」用于验证召回效果：输入关键词，看到命中片段及分数，是调参的主要依据。
- 删除文档会同步移除其检索片段并重建索引。
- 大批量导入后如检索异常，点「重建索引」。

### 5.3 竞赛推荐

1. 左下搜索框按姓名/学号/专业找到学生。
2. 可填技术方向（如"算法, 大模型"）参与打分。
3. 点「生成推荐」。

结果按匹配度排序，标注「冲刺 / 稳妥 / 保底」。每条的匹配度由规则加权得出：专业对口 +25、年级适配 +12、方向契合 +10~20、报名临近 +8、往年获奖率高 +6；专业不符 −18、年级不符 −20、报名已截止 −25、难度过高且低年级 −12。评分构成在结果里逐条列明，可复核。

### 5.4 备赛辅助

选择赛事后生成计划，含时间安排（倒排到比赛/截止日）、任务清单、材料清单，右侧同步列出规程原文片段作为依据。

### 5.5 材料评审

把申报书正文粘贴到文本框（或点「读取本地文本」载入 .txt/.md），可指定赛事以匹配评审标准。点「开始评审」得到：

- 初评得分与分维度评分
- 问题清单（严重度、位置、问题、可直接采用的改法）
- 8 条答辩预判问题

点「填入示例材料」可载入一段故意写有缺陷的文本（空话多、无数据、缺创新点），用于演示问题检出能力。

### 5.6 数据统计

- 上方四张卡片为总览指标。
- 「年度趋势」「获奖等级分布」为固定图表。
- 维度查询区：先选分组维度（年份/赛事/级别/类别/专业/教师/获奖级别/获奖等级/状态/学生），再叠加筛选条件，图表与表格同步刷新。
- 「问数」支持自然语言，如"2025 年各专业的获奖情况"，系统解析为查询条件后走数据库聚合。
- 「导出 Excel」生成含「统计汇总」与「明细」两个工作表的文件。

### 5.7 经费辅助

三个标签页：

**预算申请** — 可选关联参赛项目自动带出赛事与级别；填人数、天数、报名费、地点后测算。右侧给出明细表、校验提示和一段可直接粘贴进申请书的「预算说明」。点「导出 Word 预算申请表」生成带签字栏的正式表格。

**借款** — 选择参赛项目，自动按批复预算生成借款单要素，含金额大写、用途表述、应附单据。可导出 Word。

**报销** — 逐行录入票据（事项、金额、发票号、开票日期），勾选已备附件，点「预审」。系统检查票据要素完整性、是否超预算、科目是否错配、附件是否缺失，给出一句话结论和逐条处理意见。可导出 Word 报销单。

### 5.8 系统状态

- 运行环境：大模型接入状态、模型名、向量方式、最近一次调用错误。
- 工作流编排：8 条工作流的节点、职责、流转关系。
- 工具清单：Agent 可调用的全部工具及说明。
- 最近执行记录：每次调用的节点数、耗时、时间。

## 6. 接入学院真实数据

### 6.1 知识库（推荐直接用界面）

把学院现行的管理办法、经费细则、竞赛规程、通知、申报书模板打包拖到「知识库」页面即可。系统自动解析 PDF/Word/Excel。

导入后务必用「检索测试」验证：输入 5-10 个真实高频问题，检查命中的片段是否包含答案。命中率低通常是切块过大或文档是扫描件（无文字层）。

### 6.2 台账数据（两种方式）

**方式一：改生成脚本**

编辑 `scripts/seed.py`，把 `COMPETITIONS`、`MAJORS` 等常量替换为学院真实数据，或直接把已有 Excel 台账读进来：

```python
import openpyxl
wb = openpyxl.load_workbook("学院竞赛台账.xlsx")
for row in wb.active.iter_rows(min_row=2, values_only=True):
    # 按列映射到 Competition / Edition / Team
    ...
```

跑 `python scripts/init_all.py --force`。

**方式二：走接口导入**

`POST /api/data/...` 目前提供查询接口。若需批量写入，建议在 `scripts/` 下新增一个导入脚本，复用 `backend/models.py` 的模型与 `backend.database.db_session()`，示例：

```python
from backend.database import db_session
from backend.models import Student, Teacher, Team

with db_session() as db:
    db.add(Student(sno="2023010101", name="张三", major="软件工程", grade=2023))
```

字段定义见《数据库设计》文档。

### 6.3 新增赛事与政策（不用改代码）

- **新增赛事**：在 `competition` 表插入记录，在 `edition` 表插入对应年度届次，`rules_json` 填报名条件、材料清单、奖项设置。推荐系统与备赛、问答会立即生效。
- **新增政策文件**：上传到知识库即生效。
- **修改开支标准**：`PUT /api/finance/rules`，或在数据库 `system_config` 表改 `budget_rules` 的 JSON。
- **调整推荐权重**：`system_config` 表 `recommend_weights`（当前实现权重写在 `tools.py` 的评分函数中，如需完全可配可改为读取该配置）。

## 7. 切换数据库

默认 SQLite（零配置，适合单机演示）。多人并发或数据量上万条时换 MySQL/PostgreSQL。

**MySQL**

```bash
pip install pymysql
```

```ini
DATABASE_URL=mysql+pymysql://user:password@127.0.0.1:3306/competition?charset=utf8mb4
```

**PostgreSQL**

```bash
pip install "psycopg[binary]"
```

```ini
DATABASE_URL=postgresql+psycopg://user:password@127.0.0.1:5432/competition
```

建库后重新执行 `python scripts/init_all.py`，模型会自动建表。

注意：JSON 列在 SQLite 上以 TEXT 存储，在 MySQL 上为 JSON 类型，两边行为一致，无需改代码。

## 8. 上线部署

### 8.1 单机常驻（Windows）

```bash
python run.py --host 0.0.0.0 --port 8000 --no-reload --no-browser
```

配合 nssm 注册为 Windows 服务，或在「任务计划程序」中设置开机启动。

### 8.2 Linux + systemd

```ini
# /etc/systemd/system/competition-agent.service
[Unit]
Description=Competition Assistant Agent
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/opt/competition-agent
Environment="PATH=/opt/competition-agent/.venv/bin"
ExecStart=/opt/competition-agent/.venv/bin/uvicorn backend.main:app --host 127.0.0.1 --port 8000 --workers 2
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now competition-agent
```

### 8.3 Nginx 反向代理

```nginx
server {
    listen 80;
    server_name competition.example.edu.cn;
    client_max_body_size 50m;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_read_timeout 120s;
    }
}
```

`proxy_read_timeout` 需大于最长的一次模型调用耗时（默认 60 秒超时）。

### 8.4 安全建议

- 本系统默认无登录鉴权，适合内网或演示环境。公网部署前必须加认证（可在 Nginx 层做 Basic Auth，或接入学校统一身份认证）。
- `.env` 内含 API Key，不要提交到代码仓库。
- `data/outputs/` 里的导出文件包含业务数据，定期清理。

## 9. 备份与迁移

系统所有状态都在三处：

| 内容 | 位置 | 备份方式 |
| --- | --- | --- |
| 业务数据 | `data/app.db`（或外部数据库） | 复制文件 / mysqldump |

## 10. 常见问题

**Q：页面空白，控制台报 Vue is not defined**
`frontend/vendor/` 缺文件。执行 `python scripts/fetch_vendor.py`。

**Q：问答总是回答"知识库中暂未检索到"**
1. 看「知识库」页是否已导入文档；
2. 用「检索测试」确认能召回；
3. 把 `RETRIEVE_MIN_SCORE` 从 0.12 调到 0.05 再试；
4. PDF 若是扫描件，没有文字层，需先 OCR。

**Q：检索到的片段不相关**
切块过大。当前默认 520 字/块、90 字重叠，可在 `backend/rag/chunker.py` 调整 `DEFAULT_MAX_CHARS`，改完删文档重新导入。

**Q：配置了 API Key 但左侧仍显示"未接入大模型"**
1. `.env` 是否在项目根目录（与 `run.py` 同级）；
2. 改完是否重启了服务；
3. 看「系统状态」页的「最近一次调用错误」，通常是 Key 无效或余额不足；
4. 豆包的 `LLM_MODEL` 必须填**接入点 ID**（形如 `ep-2024xxxx`），不是模型名。

**Q：端口被占用**
`python run.py --port 8001`

**Q：导出的 Word 打不开或格式错乱**
确认 `python-docx` 已安装且版本 ≥ 1.1。用 WPS 打开可能有细微差异，建议用 Microsoft Word 或 WPS 最新版。

**Q：中文显示方框**
导出文档字体设为宋体/黑体，Windows 自带。Linux 服务器上生成时若缺中文字体，需安装 `fonts-wqy-zenhei` 等字体包，或把生成动作放在 Windows 端。

**Q：想换成官方 LangGraph**
工作流引擎接口与 LangGraph 对齐（`add_node` / `add_edge` / `add_conditional_edges` / `set_entry_point` / `compile` / `invoke`），节点函数签名为 `fn(state, ctx) -> dict`。替换 `backend/agent/graph.py` 中的 `StateGraph` 为 `langgraph.graph.StateGraph` 时，需把 `ctx` 参数改为通过 state 或闭包传入。详见《Agent 工作流与 Prompt 说明》第 6 节。
